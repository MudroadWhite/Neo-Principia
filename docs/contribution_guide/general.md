# General guideline

We're currently allowing PRs in 3 flavors:

- Formal proofs for a chapter, titled with `Proofs for chapter x, part x`. The parts are expected to be specified by some issue in the issue list when we're focusing on that part of proof.
- Documentation update, titled with `Documentation update mmddyyyy`.
- Any other kind of features, for example, setting up CI, adding more automation or external supports, should be titled with `Miscellaneous maintainence mmddyyyy`.

For all kinds of PR: please list what you have done in the description.

For PRs of proofs: please make sure...
- Your branch has passed through the GitHub Workflow.
- You code style matches up with what have been specified in our documentation.
- Your code's naming is sticking to our convention as close as possible.
